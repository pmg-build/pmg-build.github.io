# Projects & Classes sections

Adds `projects/` and `classes/` to the site without touching the existing design files.
Everything is plain HTML/CSS/JS (no build step); pages work from `file://` and GitHub Pages.

## Files
- `projects/data/projects.js` — the ONLY place projects are defined (plus `window.SITE` contact/confidentiality settings).
- `classes/data/classes.js` — the ONLY place classes are defined.
- `projects/js/*.js`, `classes/js/classes.js` — one renderer per page type. `projects/css/projects.css` — scoped under `body.pj-page`, built on the site's `styles.css` variables.
- `projects/**/index.html`, `classes/**/index.html` — GENERATED by `node tools/make-pages.mjs`. Do not hand-edit.
- `tools/check.mjs` — validation (see below).

## Add a project / class
1. Copy an existing entry in the data file and edit it (keep every field).
2. `node tools/make-pages.mjs` (creates the page, removes stale ones)
3. Add the URL to `sitemap.xml` (the check fails if missing)
4. `node tools/check.mjs` — must print `OK`. Optional full visual check (needs playwright-core + Chrome): `node tools/check.mjs --render --shots /tmp/shots`

## What every project page contains (same order, same template)
Proposal → Pricing → Documentation → Security & Frameworks → Revision history (v0.1 … ending in "End goal").
Frameworks are only ever `aligned`, `considered`, `planned` or `not-applicable`. Never "certified".

## Selective disclosure
Pricing, Documentation, Security & Frameworks and Revision history each have `visibility`:
- `summary` (default): general summary only
- `private` : same as summary but the section says detail is available on request
- `public`: the only level that may carry `detail`, document links or revision notes

The check fails if a non-public section contains detail/links/notes, or if any public data contains URLs, emails,
dollar figures, percentages, supplier or client names, "certified", unit-cost/margin wording, or (for classes) meeting times/rooms.

## Before publishing
- [ ] Confirm confidentiality of any client-related work, then set `SITE.confidentialityConfirmed = true`.
- [ ] Add your email in `SITE.contact.email` and set `showEmailPlaceholder` to false (until then the pages show "add your email").
- [ ] Replace placeholder target dates in revision histories; confirm BLOOM / Linux monitor v0.1 dates (approximate).
